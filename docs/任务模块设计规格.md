> 版本：v1（草稿，待视觉方向确认）
> 关联：Ardot 设计稿「自律App_移动端设计稿」；代码仓库 `D:\100_code\110_regular_note`
> 目的：任务模块功能、交互、数据模型的完整约定，供代码阶段直接落地，减少来回确认。

---

## 0. 模块定位
任务系统是 App 的「中枢」：习惯 / 饮食 / 运动 / 记账 / 总结等模块的数据在此汇总编排。任务页承载「待办池 + 今日任务」双栏管理。

---

## 1. 页面结构（移动端 390×844）
- **顶部栏**：标题「任务」+ 排序切换（按类型 / 按截止日期）+ 新建入口
- **主体**：当前视图（待办池 或 今日任务），单栏滚动
- **右下角**：转换按钮（FAB），在「待办池 ⇄ 今日任务」两个视图间整页切换
- **底部 Tab 栏**：今日 / 任务(高亮) / 记录 / 我的

> 说明：手机宽度下两栏并排过窄，采用「单栏 + 切换」而非并排双栏。平板 / 桌面版后续再考虑并排泳道。

## 2. 任务数据模型（代码落地用）

```ts
type TaskType = 'study' | 'sport' | 'life' | 'work' | 'other';
// 类型 → 颜色（类型色码）：
//   study 蓝 #3B82F6 | sport 绿 #22C55E | life 橙 #F59E0B
//   work 紫 #8B5CF6 | other 灰 #9CA3AF

interface Task {
  id: string;
  title: string;
  type: TaskType;
  mode: 'long' | 'short';     // 长线 / 短线
  deadline: string | null;    // 截止日期 ISO；null = 无截止
  inToday: boolean;           // 是否在「今日任务」中
  order: number;              // 当前视图内排序权重（越小越靠上）
  createdAt: string;
  updatedAt: string;
  // —— 长线任务字段 ——
  total?: number;             // 总个数（mode=long 必填）
  done?: number;              // 已完成个数
  // —— 短线任务字段 ——
  completed?: boolean;        // 是否完成（mode=short）
  returnTomorrow?: boolean;   // 明日回池（仅 short 且未完成时可勾）
}
```

---

## 3. 长线任务（long）
- 按「个数」划分，新建时设定 `total`（如 5 个）。
- 进入今日后，用户自行安排「今日完成多少个」；实际完成以 `done` 记录。
- **完成录入**：卡片上的步进器（− / +）或直接填「完成了多少」，写入 `done`。
- **进度展示**：进度环 + 文字 `done/total`，直观可见。
- **判定**：当日 `done >= 今日目标` → 标记成功；否则失败（视觉用色区分）。
- **跨日回池**：只要 `done < total`（未全部完成），次日首次打开 App 时自动回到「待办池」（`inToday=false`），并重置 `done=0` 等待重新安排。

---

## 4. 短线任务（short）
- 仅两种状态：完成 / 未完成（`completed`）。
- 未完成时，卡片显示「明日回池」开关（`returnTomorrow`）。
- 勾选「明日回池」后，次日自动回到「待办池」（`inToday=false`）。
- 不勾选则停留在今日（或手动移回）。

---

## 5. 添加任务流程
- **仅能在「待办池」添加**：待办池「+ 新建任务」，填写 标题 / 类型 / 长线·短线 / 截止日期(可无) / 长线个数。
- 添加后落在待办池，不在今日。
- 从待办池 → 今日：每张卡有「+ 今日」按钮，或右滑手势；点击后 `inToday=true`，进入今日视图。

---

## 6. 转换按钮（右下 FAB）
- 作用：整页在「待办池」与「今日任务」两个视图间切换（用户原话：右下方转换按钮，去转换待办池和今日）。
- 同时保留每张卡「+ 今日」的单项移动能力。
- 图标随当前视图变化（池 → 今日 / 今日 → 池）。

---

## 7. 排序
两种方式，顶部切换：
1. **按任务类型**：同类型聚拢（顺序 study / sport / life / work / other）。
2. **按截止日期**：升序；无截止日期排到最后。
- 排序只影响展示；手动拖动设定的 `order` 在「手动排序」模式下优先（见 §8）。

---

## 8. 拖动排序
- 每张卡有「拖动手柄」小按钮，长按进入拖动。
- **上下拖动重排**：释放后其余卡片平滑「挤开」让位（reflow 动画），并持久化新的 `order`。
- **移动端补充**：左右滑动用于快捷操作——
  - 右滑：加入今日（待办池内）/ 完成（今日内，短线）
  - 左滑：明日回池 / 删除（手势语义待确认）
- 用户原话「上下左右活动，并挤开其他卡片」**已确认**理解为：**垂直重排为主 + 左右滑动触发快捷动作**（非自由画布拖拽）。

## 9. 视觉设计方向（重点：不要普通）
当前 indigo 平铺卡片偏「工具感」。提供三个方向，请择一：

**方向 A（推荐）：看板活力风**
- 双栏以「泳道」意象呈现（待办池浅灰底、今日白卡），类型用色点 + 左侧色条编码。
- 长线任务用**进度环**（而非纯条）突出个数进度；短线用大号勾选。
- 圆角 16–20，轻投影，主色 indigo，类型色点缀；完成态整卡降饱和 + 划线。
- 拖动手柄微动效，释放回弹。

**方向 B：时间轴禅意风**
- 今日任务排成竖向时间轴（每条带进度环），待办池为侧边折叠列表。
- 配色更素（米白 + 墨绿 / 赭石），强调「自律的安静感」，适合长期陪伴。

**方向 C：Material You 胶囊风**
- 动态取色胶囊按钮、大圆角、强对比，动效多（水波纹、弹性）。更「年轻潮」，但可能偏花。

> 视觉方向待用户确认（当前默认推荐 A）。交互语义已确认：右下 FAB 切换两视图；拖拽为垂直重排 + 左右滑快捷。

## 11. 跨日回池触发时机（代码注意）
- 建议在「每日首次启动」或「跨过本地 midnight」时跑一次 rollover：
  - 遍历 `inToday` 任务：long 且 `done < total` → 回池、`done=0`；short 且 `!completed` 且 `returnTomorrow` → 回池。
- 需本地日期比对（`lastRolloverDate` vs `today`）。

---

## 12. 与 Obsidian 的关系
- 任务模块本身**不**导出 Obsidian；仅「日记 / 每日总结」导出 Markdown（见仓库 README）。任务可被引用进每日总结文字，但非强制。
